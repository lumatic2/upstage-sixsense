# 라이브 시연 대본 (발표 슬라이드 11쪽 슬롯, 약 75~90초)

> **방침 (2026-07-24 확정)**: 시연은 **라이브 URL을 직접 열어서** 한다. 영상은 제출물이자
> **라이브가 막혔을 때의 백업**으로만 쓴다. 발표자(전유성)가 직접 조작하고 말한다.
> **어디서**: 반드시 `https://sixsense.askewly.com` (제출한 Live URL과 같아야 한다. localhost 금지)

## 원칙 — 랜덤 클릭 금지

심사 55점이 데이터 처리·Upstage에 걸려 있다. 그냥 클릭만 하면 "지도 앱"으로 보인다.
**근거가 화면에 남는 순서**로만 움직인다. 75초 안에 다 못 보여주므로, 아래 코스는
**핵심(A·B) + 시간 남으면(C)** 으로 잘라 놓았다.

---

## 사전 세팅 (발표 시작 전, 시연 오퍼레이터와 함께)

- [ ] 브라우저 탭 3개를 **미리 열어 로드까지 끝내 둔다**: ① `/app.html` ② `/about.html` ③ 제출 시연 영상(백업)
- [ ] `/app.html`은 지도 타일까지 뜬 상태로 대기 — 시연 중 첫 로드에 5초 쓰지 않는다
- [ ] 검색 문장은 그 자리에서 타이핑한다 (복붙보다 라이브감이 있다 — 짧으니 부담 없음)
- [ ] 행사장 와이파이 불안 대비: 폰 핫스팟을 켜 두고 노트북에 연결 테스트까지 완료
- [ ] 발표 직전 30초 점검(아래 §점검)을 오퍼레이터가 돌린다

## 코스 A — 검색→추천→근거 (약 45초, 절대 생략 불가)

1. `/app.html` 탭으로 전환. **입력**: `8천원 이하 10분 거리 혼밥`
   - 말: *"실제로 물어보겠습니다. 8천원 이하, 10분 거리, 혼밥."*
2. 조건 칩이 뜨면 한 박자: *"방금 Solar가 문장을 예산 8천원·도보 10분·혼밥 태그로 구조화했습니다."*
3. 추천 카드 3장 + 지도 핀이 좁혀지면:
   - 카드의 **추천 이유 한 문장**을 하나만 소리 내어 읽는다 — *"이유가 전부 실데이터(메뉴·가격·도보)입니다."*
   - **요약줄을 가리킨다**: *"추천 이유는 다른 모델이 데이터와 대조해 N건이 근거 검증을 통과했습니다"*
     ← **이 줄이 근거 검증의 항상 보이는 증거다. 반드시 짚고 2초 멈춘다.**

## 코스 B — 파이프라인 증거 (약 30초)

4. `/about.html` 탭으로 전환(미리 열어 둔 것). 스크롤은 **두 지점만**:
   - **파이프라인 흐름도**: *"입력 3갈래가 사람 검수 한 문을 지나 서비스로 갑니다."*
   - **3단계 근거 검증 예시**(초안→판정→교체): *"근거 없는 문장이 실제로 이렇게 버려지고 데이터 사실로 교체됩니다."*
5. 클로징으로 전환: *"방금 보신 게 전부 라이브입니다. 지금 여러분 폰으로도 됩니다."*

## 코스 C — 시간 남을 때만 (각 +15초)

- **제보 입구**: `/contribute.html` 열어 예시 사진 클릭 → *"사진 한 장이면 Document Parse가 그 자리에서 읽고, 검수 대기줄로 들어갑니다."*
- **실행 블록**: `/about.html`의 실행 블록 하나 클릭 → *"스크린샷이 아니라 진짜 API가 지금 돕니다."*
- Q&A에서 "진짜 되냐"가 나오면 그때 이 두 개를 꺼내면 된다 — 발표 시간을 아끼는 쪽이 우선.

## 막혔을 때 — 전환 대본까지 정해 둔다

| 상황 | 행동 | 말 |
|---|---|---|
| Solar 타임아웃(조건은 뜨는데 느림) | 그대로 진행 | *"지금 폴백 경로로 동작 중입니다 — 외부 장애에도 검색은 죽지 않게 설계했습니다"* (`source: regex-fallback`도 설계다) |
| 페이지 자체가 안 뜸 | 백업 영상 탭으로 즉시 전환 | *"현장 네트워크가 불안해 녹화본으로 보여드리겠습니다. 제출된 Live URL에서 그대로 재현됩니다"* |
| 추천이 이상하게 나옴 | 당황하지 않고 요약줄로 | 근거 요약줄은 항상 뜬다 — 검증 서사로 연결 |

**전환 판단은 5초 안에.** 라이브를 살리려고 20초 새로고침하는 것이 최악이다.

## "근거 미달 → 교체" 배지에 대하여 (읽어둘 것)

이 배지는 **아무 때나 안 뜬다.** solar-pro2가 근거 없는 표현(맛·평판·분위기)을 쓴 걸 solar-mini가
잡았을 때만 붙는데, 생성 프롬프트가 그런 표현을 애초에 막아서 **거의 항상 통과한다**
(2026-07-24 실측: 15개 추천 전부 통과, 교체 0건). **억지로 띄우려 하지 말 것** — 안 뜨는 게
통제가 잘 된다는 증거고, 근거 증거는 코스 A의 요약줄로 충분하다. "교체 장면"은 코스 B의
`/about.html` 3단계 예시가 항상 그려 준다.

## 발표 직전 점검 (30초, 오퍼레이터)

```bash
curl -s https://sixsense.askewly.com/verify.html -o /dev/null -w "%{http_code}\n"
node -e "fetch('https://sixsense.askewly.com/api/parse-query',{method:'POST',headers:{'content-type':'application/json'},body:JSON.stringify({query:'8천원 이하 혼밥'})}).then(r=>r.json()).then(j=>console.log(JSON.stringify(j)))"
```

⚠ **Windows curl 로 한글 body 를 보내지 말 것** — cp949 로 전송돼 Solar 가 빈 질의로 해석한다
(2026-07-17·2026-07-24 두 번 실측, 둘 다 오경보를 만들었다). 점검은 Node fetch 나 브라우저로.

## 자주 나오는 오해

| 오해 | 사실 |
|---|---|
| "근거 배지가 안 떠서 검증이 안 도나?" | 돈다. 통과하면 배지를 **일부러 안 붙인다**(장식 방지). 검증 결과는 카드의 `data-grounded`와 요약줄에 남는다 |
| "클릭만 하면 되지?" | 절반만 맞다. **순서**가 중요하다 — 위 코스가 배점 표면(파이프라인 20·깊이 15·Upstage 20)을 지난다 |
| "영상 틀면 안전하지 않나?" | 라이브가 기본이다(2026-07-24 확정). 영상은 페이지가 안 뜰 때의 백업이고, 그때도 "제출 URL에서 재현된다"고 말한다 |
