## 1. 결과

- **데모데이**: 2026-07-25(토), 성균관대 자연과학캠 삼성학술정보관. 심사 = Upstage 현직자.
- **결과: 미수상.**
- **라이브 시연은 깔끔하게 동작했다** — 배포본 `sixsense.askewly.com` 이 무대에서 실서비스로 돌았다(영상 대체 아님).
- **결정적 실패: 발표 시간 초과.** 대본 없이 프리스타일로 발표했고, 시간을 못 맞춰 **시연 이후 과정이 통째로 스킵됐다.**
  하필 그 구간이 이 프로젝트의 심사 승부처였다 — 파이프라인(20) + 처리 깊이(15) = **루브릭 35점이 몰린 곳**.
  만든 것이 심사위원에게 닿지 못했다. 심사위원 반응 자체는 괜찮았다.
- 상위권 결: **기술·파이프라인 깊이 + 완성도·UI** (사용자 관측).

## 2. 무엇을 만들었나 (닫힌 상태)

- **서비스**: 예산을 넣으면 학식과 명륜캠 주변 식당을 한 판에 놓고 골라주는 웹서비스. 바닐라 JS + Kakao Maps + 구글 시트 + Vercel serverless. 프레임워크 없음.
- **파이프라인 3종**: 메뉴판 사진 → Document Parse → 사람 검수 게이트 / 성대 학식 HTML 크롤링(Vercel Cron 자동화) / 자연어 질의 → Solar 구조화 → 추천 + 이유 생성 + **독립 모델 근거 판정**.
- **최종 데이터**(라이브 `/api/data` 실측): 식당 50곳(54 수집) · 메뉴 580행(파싱 후보 739 중 검수 통과) · 학식 4곳. 본메뉴 428 / 사이드 152.
- **Upstage 활용**: Document Parse(`ocr=force`·`coordinates=true`) · Solar `solar-pro2`(구조화·이유) · `solar-mini`(근거 판정). 학식은 의도적으로 파싱 미적용(이미 HTML).
- **파싱 정확도 실측**: 명륜동 메뉴판 72항목 76.4%. 지배 변수 = 해상도(인쇄체·해상도 충분 100%, 저해상 흐림 20%).
- **규모**: 총 251 커밋. 마일스톤 M1~M4(7/17) → DR1~DR11(7/19~22). 검증 산출물 = `verification/matrix.md`, `experiments/parse-poc/accuracy.md`.

## 3. 프로젝트 측 판단 (해석은 회고 정본으로)

만든 물건 자체는 북극성("데이터 파이프라인의 깊이를 실물로 증명")을 달성했다 — 라이브가 무대에서 돌았고,
근거 검증·검수 게이트가 실동작했다. **닫힌 것은 제품이 아니라 전달이다.** 35점 승부처를 3주간 쌓아놓고
발표 7분 안에 그 구간을 심사위원에게 못 보여줬다. 이건 제품 결함이 아니라 발표 리허설·시간 배분의 실패이고,
HANDOFF §3-④("발표 자료가 코드보다 먼저 낡는다")가 예고한 축과 같은 계열이다 — 발표라는 표면을 코드만큼
관리하지 않았다. 상세 근본원인·다음 대회 처방은 회고 정본.
